# 고동동 CS

가상의 한정판 리셀 플랫폼 고객센터에서, 상담사가 문의에 답장을 쓰는 일을 돕는 웹 서비스입니다. 5일짜리 포트폴리오 미니 프로젝트이며, **모든 문의와 정책은 가짜입니다.** 실제 회사 이름·로고·고객 정보는 쓰지 않았습니다.

## 무엇을 하나

1. **문의 자동 분류** — 직접 학습시킨 모델이 문의를 7가지 종류(구매자: 배송·검수 결과·취소/환불·결제, 판매자: 검수 불합격·페널티·정산) 중 하나로 나누고 확신도(%)를 보여줍니다.
2. **규정 문서 근거가 붙은 답장 초안** — 규정 문서(102개 조항)에서 문의와 맞는 조항을 찾아 OpenAI로 초안을 씁니다. 초안이 말한 조항 번호는 프로그램이 다시 확인하고, 정책에 없는 내용은 지어내지 않고, 참고한 규정 문서가 하나도 없는 초안은 **"규정 문서에는 없음"**으로 표시합니다.
3. **위험 표현 경고** — "보상해 드릴게요", "판정 바꿔 드릴게요"처럼 함부로 약속하면 안 되는 말이 초안·수정본·직접 쓴 답장에 있으면 해당 문장을 보여주며 경고합니다. (막지는 않습니다.)
4. **상담사의 최종 결정** — 승인 / 수정 / 재작성(문의당 1번) / 직접 작성. 두 상담사가 동시에 처리하면 먼저 저장한 쪽만 적용됩니다. 승인해도 답장은 고객에게 실제로 발송되지 않습니다.
5. **작업 기록** — 누가, 언제, 무엇을 했는지 남기고 상담사·행동별로 거릅니다.
6. **성능 평가** — 정답이 달린 연습용 문의 140개로 분류 모델의 정확도(전체·종류별·난이도별)와 헷갈린 부분을 보여주고, 실행마다 결과를 저장해 이전 결과도 다시 볼 수 있습니다.

## 분류 모델 성적 (있는 그대로)

평가용 140개 중 **106개 정답 (75.7%)**. 쉬움 95.7% · 보통 59.5% · 어려움 50.0%.

- 글자 조각(2~3글자) TF-IDF + 로지스틱 회귀. 단어 방식보다 낫다는 것은 학습용 문의만 쓴 교차 검증으로 골랐습니다.
- 평가용 문의는 다른 생성형 AI가 만들었습니다. 다만 **평가용 문의를 본 뒤 학습용 문장을 보강했기 때문에 이 점수는 낙관적일 수 있습니다.** (보강 때 평가용과 거의 같은 문장은 걷어냈습니다.)
- 목표 정확도는 따로 두지 않았습니다. 확신도가 기준값(처음 70%)보다 낮은 문의에는 경고를 함께 띄워 상담사가 문의 종류부터 확인하게 합니다.

## 기술

| 영역 | 사용한 것 |
|---|---|
| 화면 | React 19, Vite, react-router (JavaScript), Vitest + Testing Library |
| 서버 | Python, FastAPI, psycopg(PostgreSQL), bcrypt, 세션 로그인 |
| 분류 모델 | scikit-learn (TF-IDF + 로지스틱 회귀) |
| 초안 | OpenAI API (`gpt-6-luna`), 규정 문서 근거 + 번호 검증 |
| 규정 문서 찾기 | OpenAI 임베딩(`text-embedding-3-large`, 뜻 비교). 같은 정답 표로 TF-IDF·섞기와 비교해 골랐고 실패하면 TF-IDF로 대신함 |
| DB | Supabase PostgreSQL (모든 표에 접근 제한 RLS) |

## 실행해 보기

1. `.env.example`을 복사해 프로젝트 맨 위에 `.env`를 만들고 DB 주소, OpenAI 키 등을 채웁니다. (`.env`는 Git에 올리지 않습니다.)
2. `backend/README.md`의 "처음 한 번"을 따라 모델 학습, DB 표 만들기, 가짜 데이터 넣기를 합니다. `frontend`에서는 `npm install`을 한 번 합니다.
3. 프로젝트 맨 위의 **`start-dev.cmd`를 더블클릭**하면 서버와 화면이 함께 켜지고 브라우저가 열립니다.
4. 연습용 계정(`kim` / `park` / `lee`, 비밀번호는 `backend/README.md`)으로 로그인합니다.

## 시험

- 서버 233개: `backend` 폴더에서 `.venv\Scripts\python.exe -m unittest discover -s tests -t .`
- 화면 210개: `frontend` 폴더에서 `npm test`

시험은 OpenAI를 가짜로 대신해 비용이 들지 않고, DB 시험은 임시 영역에서 돌고 끝나면 지웁니다. 새 기능마다 코드를 일부러 망가뜨려 시험이 실패로 잡아내는지도 확인했습니다. 실제 Edge 브라우저로도 주요 화면을 열어 콘솔 오류가 없는 것을 확인했습니다.

## 알아 둘 점 (한계)

- 규정 문서 102개 조항 중 4개(정산 수수료·정산 보류·정산 내역서·규정에 없는 문의 응대 원칙)는 제가 만든 **가상 조항**이고, 나머지는 공개된 서비스 안내를 바탕으로 이름·주소·전화번호·브랜드명을 지워 요약해서 다시 썼습니다. 숫자(기간·금액 등)는 시연용 값입니다.
- 답장은 고객에게 발송되지 않습니다. 사이트는 연습용 가상 상담사 계정 3개만 지원하며, 계정 관리·규정 문서 편집 화면은 없습니다.
- 초안은 OpenAI 응답에 따라 문장이 매번 조금씩 다르고, 호출할 때마다 소액의 비용이 듭니다.
- 분류 정확도는 위에 적은 대로 낙관적일 수 있습니다.
