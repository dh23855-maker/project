# 평가용 문의 만들기: Gemini에게 줄 프롬프트

사용 방법
1. 아래 **[프롬프트 1]** 의 코드 상자 안 내용을 전부 복사해서 Gemini에 붙여 넣습니다.
2. Gemini가 CSV를 보내면 복사해서 메모장에 붙이고, `backend/data/eval/eval.csv`로 저장합니다. (인코딩: UTF-8)
3. 이어서 **[프롬프트 2]** 를 Gemini에 보내 나머지 70개를 받고, 같은 파일 아래쪽에 이어 붙입니다. (헤더 줄 `text,label,difficulty`는 한 번만 둡니다.)
4. 저장하면 알려 주세요. 형식과 정답을 점검한 뒤, 정답 표시를 사용자가 훑어봅니다.

주의
- 이 파일의 문의는 **평가에만** 씁니다. 모델 학습에는 절대 쓰지 않습니다.
- 모든 문의는 가짜입니다. 실제 회사 이름, 브랜드 이름, 개인정보는 들어가지 않게 해 둡니다.

## [프롬프트 1]

```
너는 한국어 고객센터 문의 데이터를 만드는 역할이야. 아래 규칙대로 "가짜 문의"를 만들어 줘.

[상황]
한정판 상품(운동화, 가방, 시계, 의류, 전자기기 등)을 사고파는 가상의 리셀 플랫폼이 있어. 판매자가 상품을 플랫폼에 보내면 플랫폼이 "검수"(정품인지, 상태가 괜찮은지 확인)를 하고, 합격하면 구매자에게 배송해. 구매자와 판매자가 모두 고객센터에 문의를 보내.

[문의 종류 7가지와 정답 기준]
문의 한 개에는 정답이 딱 하나여야 해. 아래 정의를 정확히 지켜서 정답을 달아 줘.

구매자가 보내는 문의 (물건을 산 사람)
1. buyer_delivery : 구매자의 배송 문의. 택배가 언제 오는지, 배송 지연, 송장 조회, 배송지 변경, 오배송, 분실, 배송 완료인데 못 받음.
2. buyer_inspection_result : 구매자가 산 상품의 검수 결과 문의. 검수 합격인데 하자가 있음, 정품 의심, 검수 사진, 검수 기준, 검수가 오래 걸림, 검수 등급.
3. buyer_cancel_refund : 구매자의 주문 취소·반품·환불 문의. 취소 방법, 취소 수수료, 반품 방법, 환불 진행·금액·계좌, 환불 규정.
4. buyer_payment : 구매자의 결제 문의. 결제 오류, 중복 결제, 카드·간편결제, 할부, 쿠폰·포인트 적용, 영수증, 입금 확인.

판매자가 보내는 문의 (물건을 파는 사람)
5. seller_inspection_fail : 판매자의 검수 불합격 문의. 내가 보낸 상품이 불합격(가품 판정, 오염, 구성품 누락 등)이 났음, 사유 확인, 이의 제기, 재검수, 반송.
6. seller_penalty : 판매자의 페널티 문의. 페널티 부과 사유, 점수, 이의 제기, 이용 정지, 해제 조건, 발송 지연으로 받은 불이익.
7. seller_settlement : 판매자의 정산 문의. 판매 대금 입금 시점, 정산 금액·수수료, 정산 계좌 변경, 정산 보류, 정산 내역서.

[헷갈리기 쉬운 경계: 이렇게 정답을 달아]
- 문의한 사람이 "산 사람"이면 1~4번, "파는 사람"이면 5~7번이야.
- 구매자가 산 물건의 검수 이야기 -> buyer_inspection_result. 판매자가 보낸 물건이 불합격 -> seller_inspection_fail.
- 주문·거래를 취소하거나 반품하거나 환불금을 묻는 것 -> buyer_cancel_refund. 결제 수단·승인·영수증·중복 결제·쿠폰 적용 -> buyer_payment.
- 판매자가 페널티 때문에 불이익을 받은 이야기 -> seller_penalty. 판매 대금과 수수료 이야기 -> seller_settlement.
- 택배가 언제 오는지는 buyer_delivery. 받은 물건의 상태가 검수 기준에 맞는지는 buyer_inspection_result.
- 한 문의에 여러 이야기가 섞여 있으면, 그 사람이 가장 원하는 핵심 요청을 기준으로 정답을 하나만 달아.

[만들 개수]
이번에는 총 70개를 만들어 줘. 7가지 종류를 각각 정확히 10개씩.
각 종류의 10개는 난이도를 이렇게 나눠 줘.
- easy 5개 : 종류가 분명하게 드러나는 문의
- medium 3개 : 종류 이름이 직접 나오지 않지만 내용으로 알 수 있는 문의
- hard 2개 : 다른 종류의 단어가 같이 나와서 헷갈리기 쉽지만, 사람이 읽으면 핵심 요청이 분명히 한 종류인 문의 (예: 검수 불합격 때문에 정산이 걱정된다는 말이 나오지만 실제로는 불합격 사유를 묻는 문의)

[문장 스타일 규칙]
- 실제 사람이 쓴 것처럼 다양하게 써 줘. 한 문장짜리 짧은 글부터 3~4문장짜리 긴 글까지 섞어 줘. 전체 중 약 30%는 두 문장 이상이어야 해.
- 존댓말, 반말에 가까운 말투, 급한 말투, 화난 말투, 정중한 말투를 섞어 줘.
- 오타, 띄어쓰기 오류, "ㅠㅠ", "ㅜㅜ", "..." 같은 표현이 가끔 들어가게 해 줘. 전체의 약 10~15%만.
- 상품 종류는 운동화, 가방, 시계, 후드티, 이어폰, 카드 등 여러 가지로 해 줘. 하지만 실제 브랜드 이름이나 회사 이름, 플랫폼 이름은 절대 쓰지 마. ("한정판 운동화", "명품 가방"처럼 써.)
- 주문번호나 날짜가 들어간다면 아무 숫자나 지어내도 돼. 실제 이름, 전화번호, 주소, 계좌번호 같은 개인정보는 쓰지 마.
- 같은 문장이나 거의 비슷한 문장을 반복하지 마. 같은 시작 표현("안녕하세요 ...")을 연달아 쓰지 마.
- 문의를 보내는 사람의 입장에서만 써. 고객센터의 답변은 쓰지 마.
- 종류 이름을 그대로 문장에 넣을 필요는 없어. 사람들이 실제로 쓰는 표현으로 써 줘.

[출력 형식]
- 설명이나 인사말 없이, CSV만 코드 상자 안에 출력해 줘.
- 첫 줄은 정확히 이 헤더야: text,label,difficulty
- 문의 내용(text)은 항상 큰따옴표로 감싸고, 문의 내용 안에는 큰따옴표를 쓰지 마.
- label은 위에서 정한 영어 이름(buyer_delivery 등) 중 정확히 하나만 써. 다른 이름은 쓰지 마.
- difficulty는 easy, medium, hard 중 하나만 써.
- 줄 순서는 종류별로 모으지 말고 완전히 섞어 줘.
- 예시 형식 (이 문장들은 쓰지 마, 형식만 보여주는 거야):
text,label,difficulty
"문의 내용이 여기에 들어가요",buyer_delivery,easy
```
