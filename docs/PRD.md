# PRD: 고동동 CS (제작 주문서)

> 이 문서는 [mvp.md](mvp.md)에서 정한 내용을 "무엇을 만들어야 하는가" 기준으로 다시 정리한 제작 주문서입니다.
> 새로 정해진 내용은 없습니다. 아직 정하지 않은 것은 **미정**으로 표시했고, 맨 아래 6장에 모았습니다.
> 실제 회사 이름·로고·고객 데이터는 쓰지 않습니다. 모든 문의는 직접 만든 가짜 문의입니다.

## 1. 누가 사용하는 서비스인가

### 사용자: 고객센터 상담사

한정판 리셀 플랫폼(가상 시나리오)의 고객센터에서 문의에 답장하는 사람입니다. 아이디와 비밀번호로 로그인해서 사이트를 사용합니다. 연습용 가상 상담사 계정 3개(김상담 kim, 박상담 park, 이상담 lee)를 미리 만들어 둡니다.

### 문의를 보내는 사람 (사이트를 직접 쓰지는 않음)

| 문의한 사람 | 문의 종류 |
|---|---|
| 구매자 | 배송 / 검수 결과 / 취소·환불 / 결제 |
| 판매자 | 검수 불합격 / 페널티 / 정산 |

구매자와 판매자는 이 사이트에 접속하지 않습니다. 이들이 보낸 문의가 상담사 화면에 나타납니다.

## 2. 어떤 불편을 해결하려는가

사는 사람과 파는 사람이 모두 문의를 보내서 문의 종류가 많습니다. 상담사는 문의마다 아래 일을 반복합니다.

1. 문의를 읽고 어떤 종류인지 판단한다.
2. 검수 기준 같은 규정 문서에서 관련 조항을 찾는다.
3. 조항에 맞춰 답장을 쓴다.

이 과정에 시간이 오래 걸립니다. 또 답장에서 "보상해 드릴게요"처럼 함부로 약속하면 안 되는 말을 실수로 쓸 위험도 있습니다.

**이 서비스가 하려는 일:** 1번(종류 판단), 2번(조항 찾기), 3번의 초안까지 미리 준비해 주고, 고객에게 보내기 전의 최종 판단은 상담사에게 남깁니다.

## 3. 사용자가 각 기능으로 무엇을 할 수 있는가

### F1. 문의 자동 분류

- 상담사는 문의가 7가지 종류 중 어디에 해당하는지, 그리고 **얼마나 확실하게 나눴는지(확신도, %)** 를 문의 옆에서 바로 볼 수 있습니다.
- 분류는 직접 학습시킨 모델이 합니다.

### F2. 근거가 붙은 답장 초안

- 상담사는 문의에 맞는 답장 초안을 받습니다.
- 초안 옆에서 **어떤 규정 문서를 근거로 했는지** 조항 번호와 원문을 확인할 수 있습니다.
- 근거가 `[구버전]` 조항뿐이면 근거 옆에 "구버전 기준이라 현재와 다를 수 있음" 경고가 함께 보이고, 초안은 구버전 수치를 단정해 쓰지 않습니다.
- 초안 작성에는 OpenAI API를 씁니다.
- 초안이 말한 조항 번호가 실제 규정 문서에 있는지 프로그램이 다시 확인합니다.
- 규정 문서는 프로젝트 작성자가 텍스트로 정리해서 넣습니다.

### F3. 위험 표현 경고

- 초안에 "보상해 드릴게요", "판정 바꿔 드릴게요"처럼 함부로 약속하면 안 되는 말이 있으면 **경고를 보고 해당 문장을 확인**할 수 있습니다.
- 경고 대상 문구 목록을 화면에서 확인하고 직접 추가할 수 있습니다.

### F4. 승인 흐름 (승인 대기 / 직접 작성)

문의는 들어오면 **모두 초안이 만들어져 승인 대기**가 되는 것이 기본이고, 초안을 만들 수 없을 때만 직접 작성이 됩니다.

| 구분 | 조건 | 상담사가 하는 일 |
|---|---|---|
| 승인 대기 | 초안이 만들어졌다 (확신도가 낮거나 규정 문서가 없어도 만든다) | 초안을 보고 **승인 / 수정 / 재작성** 중 하나를 고른다 |
| 직접 작성 | 초안을 만들 수 없었다 (오류 등) 또는 재작성 뒤 넘겼다 | 초안 없이 직접 답장을 쓴다 |

- 기준값은 화면에서 바꿀 수 있습니다. 확신도가 기준값보다 낮은 문의에는 초안과 함께 "분류 확신도가 낮음" 경고가 뜹니다.
- 규정 문서에 없는 내용은 초안이 지어내지 않고, 규정 문서 자리에 **"규정 문서에는 없음"**이 표시됩니다.
- 초안은 상담사가 승인하기 전에는 고객에게 나가지 않습니다.
- **수정:** 상담사가 초안을 고치고 저장하면 바로 처리 완료되며, "수정하여 승인"으로 기록됩니다.
- **재작성:** 초안이 마음에 들지 않으면 새 초안을 받습니다. 재작성은 **문의당 1번만** 가능합니다. 두 번째 초안에서는 재작성 버튼 대신 **직접 작성으로 넘기기**가 나타나고, 그 문의는 직접 작성으로 넘어갑니다.
- **다시 수정:** 처리 완료된 문의도 [다시 수정]으로 최종 답장을 고칠 수 있습니다. 상태는 처리 완료 그대로이고, 기록에는 "수정"이 새로 한 줄 쌓입니다. 이전 기록은 지워지지 않습니다.

### F5. 작업 기록

- 상담사가 승인·수정·재작성·직접 작성을 하면, **누가 / 언제 / 무엇을** 했는지가 기록으로 남습니다.
- 나중에 기록을 다시 볼 수 있습니다.

### F7. 문의 현황

언제 어떤 종류의 문의가 얼마나 들어왔는지, 초안과 처리가 어땠는지 봅니다 (사용자 요청으로 추가). 기간을 고르고(오늘·7·14·30일), 종류별 색이 나뉜 막대 그래프와 요약(총 문의·가장 많은 종류·가장 많이 들어온 날·하루 평균), **규정 문서에는 없음 비율**(규정 문서 보강 우선순위), **확신도가 낮은 문의 비율**(분류 모델 보강 필요), **처리 현황**(초안 그대로 승인한 비율, 처리 시간)을 보여 줍니다. 자세한 동작은 spec.md 8-2장.

### F6. 성능 평가

- 정답을 미리 달아둔 연습용 문의 묶음을 **한 번에** 돌릴 수 있습니다.
- 결과로 아래를 볼 수 있습니다.
  - 전체 중 몇 개를 맞게 분류했는지
  - 종류별 정확도
  - 어떤 종류끼리 헷갈렸는지
- 분류 모델은 처음부터 가장 잘하는 하나만 씁니다. 처음 버전과 고친 버전으로 나누거나 비교하지 않습니다.

### 문의를 사이트에 넣는 방법

- 미리 만들어 둔 가짜 문의 목록이 "받은 문의"로 보입니다. 상태 탭(전체 / 승인 대기 / 직접 작성 / 처리 완료)으로 골라 볼 수 있고, 가운데 선을 끌어 목록 너비를 바꿀 수 있습니다.
- 시연을 위해 **새 문의를 직접 입력**할 수도 있습니다.

## 4. 어떤 화면이 필요한가

| 화면 | 보여주는 것 | 관련 기능 |
|---|---|---|
| 로그인 화면 | 아이디·비밀번호 입력 | 로그인 |
| 상담 화면 (메인) | 한 화면에 아래 네 가지를 모두 표시. 문의 목록(상태 탭, 너비 조절) / 문의 내용 / 분류 결과와 확신도 / 답장 초안과 위험 표현 경고 / 규정 문서 / 승인·수정·재작성 버튼 / 새 문의 입력 | F1~F4 |
| 작업 기록 화면 | 누가·언제·무엇을 했는지 | F5 |
| 문의 현황 화면 | 기간(오늘·7·14·30일)별 날짜(시간대) × 문의 종류 쌓은 막대 그래프, 요약 4개, 종류별 합계, 규정 문서에는 없음 비율, 확신도가 낮은 문의 비율, 처리 현황, 표로 보기 | F7 |
| 성능 평가 화면 | 정확도, 종류별 결과, 헷갈린 부분, 이전 실행 결과 | F6 |
| 설정 화면 | 기준값(처음 70%) 변경, 위험 표현 목록 확인·추가 | F3, F4 |

**상담 화면 배치 (대략):**

```
┌───────────────┬───────────────────────────────┐
│ 문의 목록      │ 문의 내용                        │
│  · 문의 1      ├───────────────────────────────┤
│  · 문의 2      │ 분류 결과: 취소·환불  (확신도 92%) │
│  · 문의 3      ├───────────────────────────────┤
│               │ 답장 초안  ⚠ 위험 표현 경고        │
│ [새 문의 입력]   ├───────────────────────────────┤
│               │ 규정 문서 번호와 원문              │
│               │ [승인]  [수정]  [재작성]          │
└───────────────┴───────────────────────────────┘
```

기준값 변경과 위험 표현 목록은 상담 화면이 아니라 별도 설정 화면에서 다룹니다.

## 5. 어디까지 되면 첫 버전이 완성된 것인가

아래가 모두 되면 첫 버전 완성입니다.

- [ ] 상담사가 아이디·비밀번호로 로그인하고, 로그아웃 버튼으로 나올 수 있다.
- [ ] 문의를 넣으면 7개 종류 중 하나와 확신도가 나온다.
- [ ] 모든 문의에 초안이 만들어져 승인 대기가 된다. 규정 문서 안의 내용은 규정 문서와 함께 보이고, 조항에 없는 내용은 "규정 문서에는 없음"으로 표시된다.
- [ ] 확신도가 낮은 문의는 초안과 함께 경고가 뜬다. 초안을 만들 수 없을 때만 직접 작성으로 넘어간다.
- [ ] 받은 문의를 상태 탭으로 골라 볼 수 있고 목록 너비를 조절할 수 있다.
- [ ] 초안에 위험 표현이 있으면 경고가 뜨고 해당 문장이 표시된다.
- [ ] 상담사가 승인·수정·재작성을 누를 수 있고, 직접 작성도 할 수 있다.
- [ ] 재작성은 문의당 1번만 되고, 그 뒤에도 쓰지 못하면 직접 작성으로 넘어간다.
- [ ] 처리 완료된 문의의 최종 답장을 [다시 수정]으로 고칠 수 있고, 기록이 추가된다.
- [ ] 상담사가 한 일이 기록으로 남고, 나중에 다시 볼 수 있다.
- [ ] 연습용 문의 묶음을 한 번에 돌려 정확도와 헷갈린 부분을 볼 수 있다.
- [ ] 한 화면에서 문의·분류 결과·초안·근거를 보고 버튼만 눌러 처리할 수 있다.

개발 기간은 5일입니다. 일정은 [mvp.md](mvp.md)의 8장을 따릅니다.

## 6. 이번에 만들지 않는 기능과 아직 정하지 않은 내용

### 6-1. 이번에 만들지 않는 기능

핵심 기능부터 먼저 만들고, 아래는 나중에 하나씩 붙입니다.

- 실제 고객 데이터 연결
- 실제 메일·채팅 발송 (승인된 답장이 고객에게 실제로 나가지 않음)
- 회원 가입, 비밀번호 찾기 등 계정 관리 기능
- 상담사별 통계 대시보드
- 모델 자동 재학습

### 6-2. 정해진 사용 기술 (참고)

화면은 React, 서버는 FastAPI(파이썬), 분류 모델은 scikit-learn, 초안은 OpenAI API, 저장소는 클라우드 PostgreSQL(Supabase)입니다. 비밀번호와 API 키는 `.env`에만 둡니다.

아래 14개는 처음에 **미정**이었던 항목입니다. 질문으로 하나씩 정했고, 취소선 항목은 확정된 내용을 함께 적었습니다. 지금 남은 미정 항목은 없습니다.
